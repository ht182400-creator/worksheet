# 07 小程序占位符与配置处理手册

> 对应微信小程序端（订阅消息推送 + 我的待办）的落地对接。本文聚焦**占位符从哪里来、怎么填、怎么保密、填后怎么验证**，作为 `miniprogram/` 与后端 `WX_*` 配置的权威处理依据。
>
> 工程文档导航见 [00_文档导航](./00_文档导航.md)；接口契约见 [04_API接口契约文档](./04_API接口契约文档.md) §17/§18；后端微信推送骨架见 `app/_wechat_push.py` / `app/_wx_auth.py`。

## 1. 为什么需要单独处理占位符

小程序对接涉及两类值，处理方式不同：

| 类别 | 示例 | 入库？ | 谁能填 |
| --- | --- | --- | --- |
| **非敏感占位符** | `appid` / `TEMPLATE_ID` / `BASE_URL` / `WX_APPID` / `WX_SUBSCRIBE_TEMPLATE_ID` | 可入库（本身就是你账号的公开标识） | 开发者 |
| **机密（secret）** | `WX_APPSECRET` | **绝不可入库** | 仅 `.env` / 系统环境变量 / 密钥管理 |

原则：**AI 不会替你编造这些值，尤其 `WX_APPSECRET` 绝不能经对话/代码传输**。本文给出"规范化占位符 + 安全注入 + 自检告警"的完整路径，照做即可。

## 2. 占位符总览表

| 文件 | 变量/字段 | 含义 | 敏感 | 当前占位值 | 真实值来源 | 填后验证 |
| --- | --- | --- | --- | --- | --- | --- |
| `miniprogram/project.config.json` | `appid` | 小程序 AppID | 否 | `wxYOUR_APPID_HERE` | 小程序后台「开发管理 → 开发设置 → AppID」 | 微信开发者工具可正常编译/预览 |
| `miniprogram/utils/config.js` | `BASE_URL` | 后端服务地址 | 否 | `http://192.168.1.100:8000/api/v1` | 本机 `ipconfig` 拿**局域网 IP**（非 localhost） | 待办页能拉到数据 |
| `miniprogram/utils/config.js` | `TEMPLATE_ID` | 订阅消息模板 ID | 否 | `TEMPLATE_ID_HERE` | 小程序后台「订阅消息 → 我的模板」 | 订阅授权弹窗正常、推送能下发 |
| `miniprogram/utils/config.js` | `TENANT_ID` | 租户 ID | 否 | `t1` | 固定演示值；生产按登录态映射 | — |
| `backend/.env`（或系统环境变量） | `WX_APPID` | 小程序 AppID（后端用） | 否 | `your_wx_appid_here` | 同小程序后台 AppID | `/wechat/code2session` 返回 openid |
| `backend/.env` | `WX_APPSECRET` | 小程序密钥 | **机密** | `your_wx_appsecret_here` | 小程序后台「开发设置 → AppSecret」（重置获取） | 同 code2session；**绝不入库** |
| `backend/.env` | `WX_SUBSCRIBE_TEMPLATE_ID` | 模板 ID（后端用） | 否 | `your_template_id_here` | 同小程序后台模板 | 推送接口下发成功 |
| `backend/.env` | `WX_PUSH_ENABLED` | 推送总开关 | 否 | `False` | 从 `.env` 注入（默认关闭，配置 appid/secret+模板后改 `True`） | 入库/分发触发真实推送 |
| `backend/.env` | `WX_PUSH_DRY_RUN` | 推送本地联调开关 | 否 | `False` | 从 `.env` 注入（默认关闭） | 不真正调用微信，仅构造完整请求体验证「字段映射 + 触发时机」整条链路 |
| `backend/app/config.py` | `WX_TEMPLATE_FIELDS` | 模板字段映射 | 否 | `thing1/thing2/number1/thing3` | 须与所选模板的**关键词顺序/类型**一致 | 推送内容正确 |

> 关键一致性约束：`小程序端 TEMPLATE_ID` = `后端 WX_SUBSCRIBE_TEMPLATE_ID` = `WX_TEMPLATE_FIELDS` 对应的模板，**三者必须同一份模板 ID**。

## 3. 后端密钥安全红线（务必遵守）

- `WX_APPSECRET` **绝不**硬编码进任何 `.py`、绝不写进小程序前端、绝不提交到 Git。
- `.env` 已被仓库根 `.gitignore` 忽略；`backend/.env.example` 是**无真实值的安全模板**，可入库。
- 加载机制：`config.py` 顶部用 `python-dotenv` 从 `backend/.env` 加载（缺失依赖/文件则静默降级，不影响 CI/容器）。
- 泄露处理：一旦怀疑 `WX_APPSECRET` 泄露，**立即**在微信后台「重置」AppSecret，使旧值失效。
- 验证不入库：提交后用 `git status` 确认不出现 `.env`；CI 仅用系统环境变量（如 `WORK_ORDER_DB_URL`）。

## 4. 后端环境变量注入方式

### 4.1 本地开发（`.env` 文件，推荐）

```bash
cd work_order_system/backend
cp .env.example .env          # Windows: copy .env.example .env
# 编辑 .env，填入真实 WX_APPID / WX_APPSECRET / WX_SUBSCRIBE_TEMPLATE_ID
pip install -r requirements.txt   # 含 python-dotenv
uvicorn app.main:app --reload
```

`config.py` 在导入期自动 `load_dotenv(backend/.env)`，早于所有 `os.getenv`。

### 4.2 Windows 系统环境变量（不落文件，备选）

```powershell
# 临时（仅当前 PowerShell 会话）
$env:WX_APPSECRET = "你的真实secret"

# 永久（用户级，重开终端生效）
[System.Environment]::SetEnvironmentVariable("WX_APPSECRET", "你的真实secret", "User")
```

> 注意：`load_dotenv` 默认 `override=False`——**已存在的系统环境变量优先于 `.env`**。若同时设置了系统变量和 `.env`，以系统变量为准。

### 4.3 生产 / 容器

用密钥管理（K8s Secret / 云厂商密钥中心 / Vault）注入环境变量，**不要挂载 `.env` 文件**。

## 5. 微信小程序后台配置（获取真实值）

1. **AppID**：小程序后台「开发管理 → 开发设置 → 开发者 ID → AppID(小程序ID)」。
2. **AppSecret**：同页「AppSecret(小程序密钥)」→ 点击「重置」/「生成」获取（仅显示一次，妥善保存）。
3. **订阅消息模板**：
   - 「功能 → 订阅消息 → 我的模板 → 选用/申请」。
   - 关键词需覆盖后端 `WX_TEMPLATE_FIELDS` 所用：`thing1`(工单号) / `thing2`(产品) / `number1`(数量) / `thing3`(事项提示)。
   - 拿到模板 ID 后，同步填到 `.env` 的 `WX_SUBSCRIBE_TEMPLATE_ID` 与小程序 `config.js` 的 `TEMPLATE_ID`。

## 6. 小程序端配置

- **`project.config.json` 的 `appid`**：替换 `wxYOUR_APPID_HERE` 为真实 AppID（微信开发者工具要求，否则无法编译/预览）。
- **`utils/config.js` 的 `BASE_URL`**：把 `192.168.1.100` 换成运行后端的**电脑局域网 IP**（手机真机调试必须用局域网 IP，`localhost` 无效）。端口 `8000` 与后端 `SERVICE_PORT` + 前缀 `/api/v1` 对应。
- **`utils/config.js` 的 `TEMPLATE_ID`**：替换 `TEMPLATE_ID_HERE` 为真实模板 ID。
- **微信开发者工具**：「详情 → 本地设置 → 不校验合法域名」勾选，才能访问 `http://` 局域网地址（真机发布前需在后台配置「合法域名」）。

## 7. 本地联调端到端步骤

1. 后端起服务并配 `.env`（此阶段 `WX_PUSH_ENABLED=False` 也能联调登录/待办）。
2. 本机 `ipconfig` 拿局域网 IP，填 `config.js` 的 `BASE_URL`。
3. 微信开发者工具导入 `miniprogram/`，填 `project.config.json` 的 `appid`。
4. 编译运行，看 Console 是否还有 `[config] 检测到占位符未替换` 告警（有则说明还有漏填）。
5. 真机预览需「不校验合法域名」（开发期）或后台配「合法域名」（发布期）。
6. 验证链路：`wx.login` → `POST /wechat/code2session` 换 openid → `POST /workers` 注册 → `GET /pending-tasks?assignee_openid=` 拉到本人工序。

## 8. 开启真实推送（联调/生产）

1. 申请订阅消息模板，拿到 `TEMPLATE_ID`。
2. `.env` 填 `WX_APPID` / `WX_APPSECRET` / `WX_SUBSCRIBE_TEMPLATE_ID`；`config.js` 填 `TEMPLATE_ID`，三者一致；`WX_TEMPLATE_FIELDS` 对齐模板关键词。
3. `.env` 设置 `WX_PUSH_ENABLED=True`（已从 `config.py` 硬编码改为环境变量读取，详见 §2 占位符表）。
4. 小程序端在交互点调 `wx.requestSubscribeMessage` 引导授权。
5. 后端工单入库 / 状态到"已分发(3)"触发推送；`43101`(用户未授权)静默降级为 skipped，不报错。
6. 看后端日志确认 `push ok` 或 `skipped/declined`。

### 8.4 无真实模板 ID 时的本地联调（DRY-RUN，§新增）

真实模板 ID 缺失 / 未申请时，**无法真发推送**（微信会返回 `errcode=40037` invalid template_id），但可用 `WX_PUSH_DRY_RUN=True` 验证整条推送链路：

1. `.env` 设 `WX_PUSH_DRY_RUN=True`（同时 `WX_PUSH_ENABLED` 可保持 `True` 或 `False`，dry-run 均生效）。
2. 触发入库 / 分发；后端构造完整请求体（含 `touser` / `template_id` / `data` 四字段 / `page`），**不真正调用微信 API**，日志打印 `推送 DRY-RUN` 并返回 `{"ok":true,"dry_run":true,"body":{...}}`。
3. 核对 `body.data` 的 `thing1`(工单号)/`thing2`(产品)/`number1`(数量)/`thing3`(事项提示) 映射是否正确、`page` 跳转页是否正确。
4. 验证通过后，把真实 `WX_SUBSCRIBE_TEMPLATE_ID` 填入 `.env` + `config.js` 的 `TEMPLATE_ID`，关掉 `WX_PUSH_DRY_RUN`、保持 `WX_PUSH_ENABLED=True`，即可真发。
- 配合 `04` §19 / §17、`_wechat_push.py`、`tests/test_wechat.py` 使用；对应测试案例 TC-41。

### 8.5 首页「退出登录」按钮（§新增）
首页登录状态卡片底部加了条件按钮，**已登录**显示红色「退出登录」、**未登录**显示绿色「登录」：
- 退出：`app.logout()` 清 `globalData.openid` + `wx.removeStorageSync('openid')`，并重置首页 `data`（openid/name/workerNames/registered/quota/statusText 回未登录态）。
- 重新登录：`app.login()` 重新 `wx.login` → 后端 `code2session` 换 openid → `ensureRegistered`（已有记录则跳过）→ `refreshStatus` + `loadWorkers` 刷新。
- **重要语义**：同一微信账号 `openid` 由微信决定、**不会变**；退出后重新登录会复用同一后端工人记录（保留订阅余量）。故「退出登录」= 清本地登录态，**不等于切换微信用户**。要验证真·新用户，仍用三种方式：① 模拟器「清缓存→重编」；② 真机换另一个微信账号扫码；③ 后端直接造新 openid 测 `by-openid` 404→注册分支。对应测试案例 TC-44。

### 8.6 工人端「授权手机号并绑定」按钮（§新增 getPhoneNumber）
首页第二个操作按钮「授权手机号并绑定」使用微信 `getPhoneNumber` 能力，解决"工人没填名时操作员也能对应到 openid"的问题：
- 按钮：`open-type="getPhoneNumber" bindgetphonenumber="onGetPhone"`。工人点击授权 → `e.detail.code` → 后端 `POST /workers` 带 `phone_code` → 后端用 `access_token` 调 `wxa/business/getuserphonenumber` 解码真实手机号，与当前 `openid` 同存 `workers.phone`（store.upsert_worker 仅非空才覆盖）。
- 后端降级：解码失败（网络/无效 code/未配置）仅 `log.warning` 并降级为不含手机号，**不阻断注册**（`worker.py` 已验证：fake code → 200 + phone 空）。
- 配套：`by-openid` 接口现返回 `phone`，便于后续操作员面板按手机号识别工人。改后端：`_wx_auth.phone_number_info`（新增 token 缓存 + 解码）、`WorkerORM.phone` 列（含旧库 `ALTER TABLE` 迁移）、`WorkerRegister.phone_code/phone`、`store.get_worker`。
- 注意：手机号由**工人设备授权**产生，操作员无法手敲录入（openid 只在工人 `wx.login` 时生成，操作员拿不到）；这正是此前澄清的"服务端手填手机号关联不到 openid"的根因。对应测试案例 TC-45。

## 10. 常见坑

- **BASE_URL 用 `localhost`**：真机调试无效，必须用电脑**局域网 IP**。
- **真机必须配置合法域名**：开发者工具「不校验」仅限开发，发布后微信要求 HTTPS 合法域名。
- **`WX_TEMPLATE_FIELDS` 与模板不一致**：关键词顺序/类型不符会导致下发失败或字段错位。
- **订阅消息是一次性**：每次需重新授权；长期订阅仅政务/医疗/民生等少数类目，工单派发通常不符。
- **secret 泄露**：立即在后台重置，旧值即时失效。
- **`.env` 与系统变量并存**：系统变量优先（load_dotenv 不覆盖已有环境变量）。
