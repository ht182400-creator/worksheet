# 02 数据结构文档

> 对应 V5.0 §25.1 通用约定、§26 数据模型。实现文件：`backend/app/models.py`（Pydantic）、`backend/app/db.py`（ORM）、`backend/app/config.py`（常量/错误码）、`backend/app/responses.py`（统一响应体）。
>
> 本文聚焦**内存/接口层数据结构**（请求体、响应体、枚举、JSON 结构），表结构见 [01_数据库结构文档](./01_数据库结构文档.md)。

## 1. 统一响应体（§25.1）

```json
// 成功
{ "code": "0", "data": <任意>, "traceId": "uuid" }
// 业务错误
{ "code": "BIZ_*", "message": "友好描述", "traceId": "uuid" }
```

- `code="0"` 成功；`code` 以 `BIZ_` 开头为业务错误（见 §4 错误码表）。
- `traceId`：每次响应生成 UUID，用于链路追踪（§14.6 OpenTelemetry 关联）。
- 状态码：成功 `200`；业务错误按语义 `400/403/404/409/422/500`（见 §4）。

## 3. 枚举与常量（状态/枚举，`state_machine.py` + `config.py`）

### 3.1 主状态枚举（work_orders.state，0-6）

| 值 | 常量 | 含义 |
| --- | --- | --- |
| 0 | `STATE_PENDING_RECOGNIZE` | 待识别 |
| 1 | `STATE_PENDING_REVIEW` | 待审核 |
| 2 | `STATE_PENDING_DISTRIBUTE` | 待分发（默认） |
| 3 | `STATE_DISTRIBUTED` | 已分发（含 3a 生成 / 3b 打印确认） |
| 4 | `STATE_PRODUCING` | 生产中 |
| 5 | `STATE_COMPLETED` | 已完成 |
| 6 | `STATE_CLOSED` | 已关闭（终态，不可变；纠错走红冲工单） |

### 3.2 二维码子态（qrcode_print_tasks.state）

- `3a_GENERATED`：已生成（BR-21）
- `3b_PRINTED`：已打印确认

### 3.3 报工状态（reports.status）

- `VALID`：有效
- `WITHDRAWN`：已撤回

### 3.4 冲突策略（conflict_logs.strategy）

- `LOCAL_PENDING`：本地优先待复核（默认）
- `SERVER`：以服务端为准
- `MERGED`：合并

### 3.5 OCR 任务状态（ocr_tasks.status）

- `QUEUED`：已入队
- `DONE` / `FAILED`：终态（演示 `get_ocr_task` 固定返回 `DONE`）

### 3.6 前端可见按钮（state-machine 端点驱动，禁止硬编码，D3）

| 状态 | visible_buttons |
| --- | --- |
| 0 待识别 | `OCR_RETRY` |
| 1 待审核 | `APPROVE`, `REJECT` |
| 2 待分发 | `BACK_REVIEW`, `GEN_QRCODE` |
| 3 已分发 | `CONFIRM_PRINT`, `REPRINT` |
| 4 生产中 | `REPORT`, `CLOSE` |
| 5 已完成 | `CLOSE` |
| 6 已关闭 | （无） |

## 5. JSON 结构样例

### 5.1 OCR 结果（ocr_tasks.result，BR-20）

```json
{
  "taskId": "uuid",
  "status": "DONE",
  "result": {
    "fields": [
      { "key": "display_no", "value": "WO-2026-001", "confidence": 0.98 },
      { "key": "qty",        "value": "1000",        "confidence": 0.99 }
    ],
    "docConfidence": 0.95,
    "needReview": false
  }
}
```
整单阈值 `OCR_DOC_CONFIDENCE_THRESHOLD=0.60`；关键字段错上限 `OCR_KEY_FIELD_ERROR_LIMIT=3`。

### 5.2 冲突审计（conflict_logs.audit，JSON）

生产填充操作轨迹（本地版本/服务端版本/裁决人/时间）。当前骨架 `audit` 预留 `JSON` 列，`resolve_conflict` 写入 `strategy` / `resolved_by`。

### 5.3 大屏 SSE 事件（bigscreen，§25.2.8）

```
event: metrics
data: {"kpi":{"producing":12,"completed_today":348,"exception":2,"online_workers":26},"server_ts":"2026-07-23T...Z"}
```
前端据 `server_ts` 计算新鲜度（`BIGSCREEN_STALE_WARN_SECONDS=30` 警告，`BIGSCREEN_SNAPSHOT_SECONDS=300` 静态快照，BR-19 / D5）。
